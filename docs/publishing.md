# 公开源码前的核对

此流程准备源码，不自动创建 GitHub 仓库、提交、推送或发布 Release。

## 检查并导出

```bash
npm run release:check
npm run release:source
```

也可以在安装依赖前直接执行 `python3 scripts/release.py`。导出使用 `--export release/taildesk-source.zip`。

检查工具读取 Git 的候选文件（已跟踪及未忽略文件），并检查现有暂存区；尚未初始化 Git 时，在临时 Git 目录中评估本项目的忽略规则，不会修改工作目录的 Git 状态。它拒绝私有路径、符号链接、未纳入公开范围的文件和二进制文件，并检查常见密钥格式、本机用户路径、非示例部署域名及设备地址。若本地存在访问密钥，也会在内存中检查其是否出现在候选文件中。发现问题时只报告文件和类别，不打印命中内容。

源码 ZIP 仅包含通过检查的工作区文件。它不包含 `.env`、`.data`、`.context`、`artifacts`、虚拟环境、依赖目录、构建产物、Git 历史或发布输出。包内时间戳和权限统一，不携带本机用户名或原文件时间。

**这不是对所有秘密的完整检测。** 新增账号、联系方式、截图等内容仍需人工检查。工具检查当前文件和暂存区，不扫描已有 Git 提交历史；修改过的旧历史需要单独处理。源码包也不代表已有仓库的历史已经清理。

## 第一次发布

1. 运行检查、测试和构建，导出源码包。
2. 将源码包解压到新的空目录，查看 README、配置示例和文件清单。
3. 在该目录初始化自己的 Git 仓库；检查 Git 作者名称和邮箱是否适合公开。可使用 GitHub 提供的 noreply 邮箱。
4. 添加文件后审查 `git diff --cached` 和 `git status --short`，再运行一次发布检查。
5. 创建自己的 GitHub 仓库并提交、推送。首次托管测试结果在 Actions 页面查看。

不要上传整个日常运行目录，也不要使用 `git add -f` 强行加入被忽略的私有文件。
